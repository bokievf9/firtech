# Пульт, этап 2: цифры трафика и Vibely

Блок «Трафик за 7 дней» в колонке чисел на `/admin`. Грузится в браузере после страницы через
`GET /api/admin/stats` (сессия владельца обязательна), так что медленный источник не тормозит экран.
Кеш на сервере: Метрика 10 минут, Vibely 5 минут. Источник без настройки показывает «не подключено»,
а не нули.

## Яндекс Метрика (счётчик 113665084)

Нужен OAuth-токен только на чтение. Его создаёт владелец, это пять минут:

1. Открыть https://oauth.yandex.ru/client/new и войти аккаунтом, которому принадлежит счётчик.
2. Название любое (например, «Fir Tech Pulse»), платформа «Веб-сервисы», Callback URI:
   `https://oauth.yandex.ru/verification_code`.
3. Доступы: «Яндекс Метрика», пункт «Получение статистики, чтение параметров своих и доверенных
   счётчиков» (`metrika:read`). Больше ничего не отмечать.
4. Сохранить приложение, скопировать его ID и открыть
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>`.
   Нажать «Разрешить», токен покажется на странице (живёт около года).
5. Положить на сервер самому, в чат не слать:
   `METRIKA_TOKEN=<токен>` в `shared/.env.production` (chmod 600), затем перезапуск через
   выкладку или `pm2 restart` по инструкции из `CLAUDE.md`.

`METRIKA_COUNTER_ID` по умолчанию 113665084, менять не нужно. Токен только читает статистику, цели и
счётчик изменить им нельзя. В репозиторий, лог и ответ API он не попадает.

Что берём: визиты, люди и просмотры за 7 дней, визиты по дням и 5 главных источников. Цели
(`track()`) в панель добавим, когда владелец создаст их в интерфейсе Метрики и назовёт идентификаторы.

## Vibely: приёмник

Fir Tech сам ходит за цифрами на локальный адрес Vibely, наружу ничего не открывается.

- Адрес: `VIBELY_METRICS_URL`, по умолчанию `http://127.0.0.1:3000/api/internal/metrics`. Принимается
  только `http` и хост `127.0.0.1`, `localhost` или `[::1]`, иначе секрет не отправляется.
- Секрет: `VIBELY_METRICS_SECRET` в `shared/.env.production` Fir Tech, заголовок запроса
  `x-metrics-secret`. Тот же секрет Vibely кладёт в свой `.env`. Без секрета блок Vibely выключен.
- Ответ Vibely читается по полям: всё, что не является числом из списка ниже, отбрасывается, поэтому
  имя, телефон, id или ссылка на фото на экран и в Echo попасть не могут.

Форма ответа `GET /api/internal/metrics` (JSON, только числа, даты `YYYY-MM-DD`):

```json
{
  "generatedAt": "2026-10-19T05:00:00Z",
  "users": { "total": 0, "signups30d": 0, "dau": 0, "wau": 0 },
  "activity": {
    "matches7d": 0,
    "messagesByDay": [{ "date": "2026-10-19", "count": 0 }],
    "callsByDay": [{ "date": "2026-10-19", "count": 0 }]
  },
  "moderation": { "selfiePending": 0, "selfieLongestWaitHours": 0, "openReports": 0 },
  "money": { "payments30d": 0, "activeSubscriptions": 0 },
  "pushOptInShare": 0.0
}
```

Правила для стороны Vibely: демо-профили не считать; дни считать по одному часовому поясу и отдавать
не больше 31 дня; секрет сравнивать за постоянное время; отвечать 401 без заголовка, слушать только
localhost, nginx наружу `/api/internal/` не отдаёт. Типы и разбор: `src/lib/traffic-types.ts`,
`src/lib/vibely-metrics.ts`. Тесты: `tests/pulse-stats.test.mjs`.

## Состояние стороны Vibely

Эндпоинт готов в Vibely (ветка `feat/internal-metrics`, коммит `ef8bd29`), не выложен до «ок»
владельца. Дни идут по часовому поясу Asia/Kuala_Lumpur, по 31 записи, старые первыми. Демо,
сотрудники и тестовые аккаунты не считаются. `payments30d` включает оплаченные и возвращённые заказы,
как денежная панель админки. Ответы: 401 нет или неверный секрет, 503 секрет не задан или короче 32
символов, 403 если запрос пришёл с заголовками прокси (поэтому Fir Tech ходит на
`http://127.0.0.1:3000` напрямую, без `x-forwarded-for` и подобных).

При выкладке владелец один раз делает `openssl rand -hex 32` и кладёт одно и то же значение в
`VIBELY_METRICS_SECRET` обоих серверных env (Vibely и Fir Tech), не печатая его.
