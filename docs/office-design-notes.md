# Живой офис: заметки по референсам (2026-11-19)

Галереи просмотрены через WebFetch (страницы отдают в основном списки названий, без таймингов и
размеров), поэтому часть пунктов выведена из названий категорий и доработана по опыту. Текстов и
картинок сайтов не копируем.

## Что взято
- **motionsites.ai**: ряд фильтр-чипов и сегментный переключатель сортировки. Берём для шапки:
  компактные чипы-счётчики (одобрения, issues) и один выделенный акцент (lime) на всю шапку.
- **navbar.gallery**: липкая верхняя панель без выпадающих меню, вторичный слой навигации.
  Берём: пункт «Офис» просто ещё одна пилюля в существующем sticky-хедере админки, без
  перестройки; на мобильном строка ссылок прокручивается по горизонтали.
- **footer.design**: бейджи-статусы и плотные однотипные карточки (иконка, имя, одно действие,
  счётчик «1 / N»). Берём: карточка исполнителя одной высоты, статус-чип справа, счётчик
  «40 из 40» над лентой.
- **cta.gallery**: баннер с одной кнопкой «Повторить» над контентом и вторичной ссылкой. Берём:
  плашка «HQ не отвечает» сверху с кнопкой «Проверить сейчас», данные под ней приглушены.
- **404s.design**: конкретная формулировка вместо «ошибка» и характерный тон. Берём: заголовок
  «HQ не отвечает» + одна строка, что видно сейчас («показываем данные N мин назад»), и
  пустое состояние с крупным значком без данных, если их ещё не было.
- **unsection.com**: сетки равновесных карточек и панели «потребление против лимита».
  Берём для расходов: число + тонкая полоса доли отдела.
- **bentogrids.com**: страница без контента; пропорции выбраны сами: 12 колонок, зазор 16 px,
  радиус 20 px (rounded-card), кабинеты 8 колонок (Marketing на всю ширину, остальные 2x2),
  лента 4 колонки, нижний ряд три плитки по 4.
- **60fps.design**: заполнение прогресса и пульс рамки. Берём: «дыхание» точки working
  (scale 1 до 1.35 и opacity, 2.4 с, ease-in-out), полоса доли расходов растёт через
  transform: scaleX; всё только transform и opacity.

## Движение
- Новая строка ленты: translateY(-8px) и opacity 0 до 1, 420 мс, ease-out-expo (токен проекта).
- Дыхание: 2.4 с, infinite, плавная кривая, без мигания (opacity не ниже 0.45).
- Смена данных не анимируем (числа просто обновляются), чтобы опрос раз в 10 с не дёргал экран.
- `prefers-reduced-motion`: все анимации выключены, точка статична.

## Статус-чипы
working (lime, дышит), waiting (нейтральный с lime-контуром), blocked (danger), idle (нейтральный),
sleeping (приглушённый), offline (пунктирная рамка), paused (нейтральный, пунктир). Цвет всегда
дублируется словом, не только оттенком.

## Пиксельный офис (2026-11-19)

С 2026-11-19 вместо bento-сетки на `/admin/office` живёт пиксельный офис в духе Lumio
(lumiomac.com): разрез здания сбоку, у каждого агента стол и человечек, поведение которого
показывает статус. Данные и опрос прежние (`/api/admin/office`, 10 с / 60 с, мок без
`HQ_OFFICE_URL` в dev). Код: движок `src/components/pixel-office/` (общий с публичным героем), обёртка админки `src/components/admin/office/pixel-office.tsx`, тесты
`tests/pixel-office.test.mjs`.

### Модули
- `sprites.ts`: спрайты строками, один символ = один пиксель, `.` прозрачный, остальные символы
  это ключи палитры. Люди 12 x 16 стоя и 12 x 14 сидя, смотрят вправо (сцена зеркалит).
  Кадры: `stand`, `hand`, `walkA/B`, `coffee`, `sit`, `typeA/B`, `sleep`; мебель: `chair`,
  `imac`, `plant`, `coffeeMachine`, `cooler`. `parseSprite` проверяет ширину строк.
- `palette.ts`: палитра сцены (своя, не зависит от темы админки), цвета стен по отделам,
  `agentLook(id, role)`: цвет рубашки, волос и кожи по хэшу id (FNV-1a), стабилен между
  загрузками. Руководители в тёмном пиджаке с красным галстуком, директор в костюме с lime-галстуком.
- `font.ts`: пиксельный шрифт 3 x 5 (латиница, цифры, немного знаков) для табличек. Кириллицы нет:
  если заголовок отдела не пишется шрифтом, на табличке будет id отдела.
- `layout.ts`: геометрия. Этажи сверху вниз, комнаты в порядке: Director, Meeting, отделы в
  порядке HQ, Builders, Lounge, Servers; жадная укладка в ширину 372 px, остаток делится между
  комнатами этажа; лестница слева. Раскладка зависит только от структуры (id и порядок отделов,
  агентов, продуктов: `layoutSignature`), не от статусов, поэтому стол не «прыгает».
  25 агентов помещаются в 400 x ~270 логических px (x3 = 1200 CSS px, 4 этажа максимум).
- `behaviour.ts`: статус в цель (`targetFor`), маршрут через лестницу (`planPath`), свет комнаты
  (`roomLight`), походы застрявших к билдерам (`errandActive`).
- `sun.ts`: местный час в `tz` из JSON (по умолчанию Asia/Tashkent) и небо: восход 06:30,
  закат 17:30, сумерки по часу в обе стороны; ночью звёзды и огни города в окнах.
- `paint-static.ts`: два кэшированных слоя (задний: небо, здание, стены, окна, таблички, стулья,
  мебель; передний: столы, мониторы, стойки, терминал). Перерисовываются только при смене
  раскладки, неба (раз в 6 мин) или счётчиков (issues, задачи, одобрения).
- `scene.ts`: живой слой на `<canvas>`, свой цикл `requestAnimationFrame`, хит-тест по
  прямоугольникам спрайтов. React только передаёт данные (`setData`) и спрашивает, что под
  курсором. Цикл стоит на скрытой вкладке.
- `pixel-office.tsx`: обёртка: целый масштаб 2..4 по ширине блока (на телефоне сцена
  прокручивается вбок, страница нет), `devicePixelRatio`, `image-rendering: pixelated`,
  пузырь при наведении (DOM, задача агента), панель по клику (не модалка, Esc закрывает).

### Что чем показано
| Статус | В сцене |
| --- | --- |
| working | сидит за столом и печатает (2 кадра), экран светится и мерцает, бегут строки кода |
| waiting | стоит у стола с поднятой рукой, пузырь «!», табличка отдела подсвечена lime |
| blocked | стоит у стола, красный пузырь «X»; если есть открытые issues билдера, раз в 60-80 с ходит к терминалу Builders и обратно |
| idle | в Lounge с кружкой (пар) или болтает («...»); директор при idle сидит за своим столом |
| sleeping | спит за столом, плывут «Z», экран-заставка; комната без бодрствующих приглушена |
| paused | человека нет; если на паузе весь отдел, свет выключен и висит табличка PAUSE |
| offline | стол пустой, монитор чёрный |

Смена статуса в опросе запускает ходьбу (30 px/с, вертикаль только по лестнице); уход
(paused/offline) это прогулка к лестнице и исчезновение, возвращение начинается с лестницы.
`quietHours: true` приглушает все комнаты. Builders: терминал показывает `#N` открытых issues,
на доске по красному стикеру на issue (до 8). Servers: стойки Dono и Polly, светодиоды по статусу
продукта. Стопка бумаг на столе директора = одобрения в очереди (до 6 листов). Доска в Meeting:
столбики задач running / review / approval / blocked / done.

`prefers-reduced-motion`: люди переходят к цели без ходьбы, кадры меняются раз в 0,8 с,
мерцание и покачивание выключены.

### Как расширять
- Новый спрайт: добавить массив строк в `RAW` в `sprites.ts` (ключи только из `BASE`, тест это
  проверяет), нарисовать через `spriteCache` в `scene.ts` или `paintSprite` в статических слоях.
- Новая комната: вид в `RoomKind`, минимальная ширина в `MIN_W`, место в списке `drafts`
  (`buildLayout`), отрисовка в `paintRoomBack`.
- Новый статус в контракте: `AgentStatus` в `office-view.ts`, ветка в `targetFor`, подпись в
  `admin.office.status`. Неизвестный статус сцена показывает как offline.

### Пробелы контракта, замеченные при сборке
- `openBuilderIssues` есть только общий: по отделам не разбит, поэтому к терминалу ходят все
  застрявшие, когда открыт хотя бы один issue. Нужен `departments[].builderIssues` или
  связь issue с задачей.
- У директора нет `currentTask`, `tasksToday` и `lastActiveAt` (есть только `lastSummaryAt`,
  его панель и показывает как «был активен»).
- `departments[].title` приходит по-английски и идёт на табличку как есть; кириллица на табличку
  не попадёт (в шрифте её нет), будет id отдела.
- Нет отметки, что агент сейчас на встрече или с кем-то говорит: Meeting пока пустая.

## Пульт (этап 1, 2026-11-19)

С 2026-11-19 `/admin/office` это рабочее место владельца («Пульт»): всё, что он делает в боте
Директора, делается здесь, а Telegram остаётся запасным каналом, когда его нет за Mac.
Пиксельный офис остаётся первым экраном.

### Карта страницы
1. **Верхняя панель** (`control/control-center.tsx`, `presence-switch.tsx`): заголовок, статус связи
   с HQ («HQ на связи» / «HQ не отвечает: причина», метка «демо-данные» у мока), два счётчика-кнопки
   (непрочитанные, одобрения; прокручивают к панели) и большой переключатель «На месте» /
   «Не на месте». Под ним строка, что реально делает HQ (effective): «уведомления приходят сюда»,
   «идут в Telegram» или красным «HQ не слышал пульт и переключил на Telegram» (авто-уход).
   Подсказка (i) объясняет авто-уход: нет отметок дольше `awayAfterMin`.
2. **Живой офис** (`office/office-board.tsx`, без изменений сцены): клик по человеку фильтрует
   задачи по нему, клик по названию отдела в «Люди по отделам» по отделу, директор сбрасывает
   фильтр. Сцена центрируется, масштаб целый: 2x до ~1250 px, 3x, 4x от 1920.
3. **Бенто-панели** (`control/cc-panel.tsx`, сворачиваются, выбор в localStorage):
   - **Входящие** (`inbox-panel.tsx`): новые сверху, иконка по виду, непрочитанные подсвечены
     и с точкой, клик = прочитано и переход (к карточке одобрения или в шторку задачи),
     «Всё прочитано», метка «ушло в Telegram». Опрос 10 с / 60 с на скрытой вкладке.
   - **Одобрения** (`approvals-panel.tsx`): самые старые сверху; текст с карандашом «Править»
     (сохраняет `edit`, карточка остаётся), «Одобрить» / «Отклонить» оптимистично (ошибка
     возвращает карточку, `already_decided` убирает её с тостом), замок у `locked` (деньги или
     content_item) просит второе нажатие, части content_item выбираются чипами (`part`).
     Клавиши A / R на выбранной карточке (и Ф / К в русской раскладке). Сверху плашка
     «В очереди на 10:00: N» с кнопкой «Выпустить сейчас» (`/command approve`).
   - **Задачи** (`tasks-panel.tsx`): чипы отделов + чип человека из офиса; колонки
     inbox / assigned / running / review / approval / blocked / done today. Container query:
     от 64rem ширины панели канбан из 7 колонок, уже это список по статусам (пустые скрыты).
     В работе видна живая `progressLine`, у застрявших причина и «Повторить» (`retry`).
     Клик открывает шторку справа (`task-drawer.tsx`): описание, результат, факты, родитель,
     одобрения, подзадачи, журнал событий; Esc и фон закрывают, фокус возвращается.
   - **Директор** (`director-chat.tsx`): поле + Enter, текст идёт в `/say`, строка с `/` в
     `/command`; ответы как сообщения (HTML бота в простой текст), созданная задача чипом,
     быстрые команды /status /tasks /approve /costs /builders; последние 50 сообщений в
     sessionStorage.
   - **Учения** (`drill-panel.tsx`): отдел, «Запустить учения» (`POST /drill {arg: dept}`),
     «Таблица» (`GET /drill`), «Очистить» (`{arg: 'clear'}`), моноширинный текст с эмодзи;
     после запуска таблица обновляется раз в 3 с минуту.
   - Старые блоки офиса (лента, люди, рутины, воронка, расходы) под кнопкой «Лента, рутины,
     воронка и расходы», свёрнуты по умолчанию.
4. **Телефон**: панели стопкой, снизу липкий таб-бар (Офис, Входящие, Одобрения, Задачи,
   Директор, Учения) с бейджами; активный по IntersectionObserver.

### Сетка и ширина
`AdminShell wide`: контейнер `max-w-[max(1760px,88vw)]`, то есть до 1760 px на всю ширину, дальше
поля растут пропорционально (2560 даёт ~2250 px). lg (1024+): 12 колонок, ряд 1 Входящие /
Одобрения / Директор по 4, ряд 2 Задачи на всю ширину, ряд 3 Учения. От 120rem (1920): 14 колонок,
в один ряд Входящие 3, Одобрения 3, Задачи 5, колонка 3 с Директором и Учениями друг под другом.
Брейкпоинт в rem, не в px: Tailwind 4 сортирует `min-[1920px]` раньше `lg:` (разные единицы),
и `lg:` его перебивал.

### Движение
Новые строки входящих, карточки и сообщения: opacity + translateY 8 px, 280-420 мс,
ease-out-expo; уходящая карточка одобрения уезжает вправо 24 px за 180 мс; таблетка переключателя
присутствия ездит пружиной (`layoutId`); шторка задач пружина по X. Высоту не анимируем (сворачивание
только проявлением). Всё в `MotionConfig reducedMotion="user"`.

### Референсы
- **bentogrids.com**: страница без содержимого (только заголовок), взяли сам принцип: плитки разной
  ширины на общей сетке с одинаковым зазором и радиусом, главная плитка (Задачи) шире.
- **60fps.design**: WebFetch не пустил (домен не проверен); из прошлых заметок: только transform и
  opacity, пружина для шторки и переключателя.
- **unsection.com**: из каталога взяли плотные карточки с меткой категории и одним действием
  (карточки задач и одобрений: метка, заголовок, одно главное действие).
- **navbar.gallery**: категории Static/Sticky и «tabs»: липкая шапка админки остаётся, на телефоне
  отдельная нижняя липкая панель вкладок вместо второй верхней.

### Прокси API
Браузер ходит только в `/api/admin/hq/[...path]` (`src/app/api/admin/hq/[...path]/route.ts`):
сессия админки, Origin у POST, белый список методов и путей с zod-схемами тел и списком query-ключей
(`ENDPOINTS` в `src/lib/hq-admin.ts`), иначе 404/400 без обращения к HQ. Запрос к
`HQ_ADMIN_URL` (по умолчанию `http://127.0.0.1:8787/admin`) с заголовком `x-admin-token`
(`HQ_ADMIN_TOKEN`, запасной `HQ_OFFICE_TOKEN`), таймаут 5 с. Ошибки HQ отдаются как
`{ ok:false, error }` с HTTP 200 (`hq_timeout`, `hq_unreachable`, `hq_unauthorized`, `hq_error`,
`hq_bad_response` или код самого HQ, например `already_decided`). Без `HQ_ADMIN_URL` в dev работает
мок с состоянием в памяти (`src/lib/hq-admin-mock.ts`, те же люди и номера задач, что в
`office-mock.ts`). Типы и чистые функции панелей: `src/lib/hq-admin-view.ts`, тесты
`tests/hq-admin.test.mjs`. Пинг: сразу при открытии, раз в 60 с пока вкладка видна и при
возвращении на неё; скрытая вкладка не пингует, поэтому HQ сам уходит в «не на месте».

### Отличия от контракта и допущения
- Учения: «Таблица» = `GET /drill`, «Очистить» = `POST /drill {arg: 'clear'}`, запуск по отделу
  `{arg: '<dept id>'}` или пустой `arg` для всех. Если бот ждёт другие аргументы, поменять в
  `drill-panel.tsx`.
- `part` у правки и решения отправляется только когда выбрана часть; иначе действие на всё.
- Задачи берутся одним запросом `tasks?limit=300`, фильтр по отделу и человеку на клиенте
  (мгновенно при клике в офисе). «Готово» показывает только сегодняшние по `tz` HQ.
- Поле `mock: true` в `/state` есть только у мока.

### Этап 2: CRM
Добавить панели и шторки по тем же правилам (прокси-эндпоинты в `ENDPOINTS`, мок, view-модель с
тестами): **Лиды** (заявки сайта и бота, статусы, кто ведёт, быстрые ответы через агента),
**Проспекты** (списки Prospector, статусы new / proposed / sent / replied, из воронки офиса),
**Клиенты** (карточка: контакты, проекты, счета, история), **Тикеты** поддержки (SLA, кто взял,
переписка), **Счета** (выставлены / оплачены / просрочены, деньги всегда под замком одобрения),
**Проекты** (этапы, сроки, связь с задачами отделов). Клик по комнате отдела в офисе должен
открывать его CRM-срез; для этого сцене нужен хит-тест по комнатам (`HitTarget` kind `room`).
