# Пульт v3: офис как хаб и CRM с панелями (2026-11-20)

Владелец: «внедрить всё в наш пиксельный офис и сделать полноценную CRM с отдельными панелями». Длинная колонка панелей
(этапы 1 и 2) убрана: `/admin/office` теперь пиксельный офис на весь экран, отделы открываются панелями поверх него.
Контракт с HQ: `pult-v3` (HQ: `agents/docs/admin-crm-api.md`), прежние маршруты: `agents/docs/admin-crm-api.md`.

## Офис-хаб
- Код: `src/components/admin/hub/hub.tsx` (состояние, опросы, клавиши), `side-panel.tsx`, `panels.tsx` (реестр вкладок),
  `command-palette.tsx`, `notifications.tsx`, `feed.tsx`, `ui.tsx` (`useHqView`, `Offline`, `CopyButton`, `useConfirm`).
- Сцена: `scene.setZoneHits(true)` делает каждую комнату целью клика (после людей, столов, стоек и вывесок),
  `setZoneGlow({roomId: 0|0.5|1})` зажигает мягкую лампу на столах (янтарь = ждёт владельца, лайм = есть работа),
  `zoneRect(roomId)` даёт прямоугольник для бейджа. Обёртка `components/admin/office/pixel-office.tsx`: пропсы `zones`
  (имена, бейджи, уровни, `onZone`), `fill` (на весь контейнер), `personAction` (кнопка «Задачи» в карточке человека).
- Комнаты и панели (`roomPanel` в `src/lib/pult.ts`): кабинет директора и переговорная = Директор; маркетинг; продажи и
  ресепшен = Продажи; поддержка; производство и билдеры = Производство; бэк-офис; серверная = Компания; лаунж ничего не открывает.
- Бейджи и лампы: `GET /admin/hub` → `departments` (одобрения, тревоги, в работе; лампа: одобрения или тревоги = 1, `pending` = 0,5).
- Верхняя полоса: присутствие («На месте» / «Не на месте», пинг раз в минуту как раньше), четыре счётчика (одобрения из
  `/admin/approvals`, новые лиды `stage=new`, счета `issued`, открытые тикеты из `crm/summary`), поиск `⌘K`, тема, меню.

## Клавиши
| Клавиша | Что делает |
|---|---|
| `1`-`6` | Директор, Маркетинг, Продажи, Поддержка, Производство, Бэк-офис |
| `7` | Компания (серверная) |
| `⌘K` / `Ctrl+K` | палитра: отделы, вкладки, команды (Пакет недели, Отчёт, Учения, Расходы, Выпустить одобрения), лиды, клиенты, проекты, счета (`?q=` в HQ), контент открытой недели |
| `Esc` | закрыть ящик, затем панель |
| стрелки | вкладки панели; карточки канбана (Shift+←/→ переносит в соседнюю колонку, Enter открывает); строки счетов |

Цифры и Esc не срабатывают, пока открыт модальный ящик или курсор в поле ввода.

## Панели
- **Директор**: Входящие (уведомления из `hub.inbox`: время, отдел, ссылка `<panel>:<id>` открывает панель на объекте),
  Одобрения (карточки с Одобрить / Править / Отклонить, как раньше), Задачи (доска и ящик задачи), Чат с Директором, Лента
  офиса, Учения.
- **Маркетинг**: Контент (`GET /admin/content?week=`: неделя из 7 колонок, карточки с превью; ящик: MP4 через
  `/api/admin/files/*`, карусель PNG, подписи по платформам с копированием, Одобрить / Правки с текстом / Отклонить /
  Опубликовано (площадка) / Пересобрать, «Из статьи: slug»), Цифры (`GET /admin/metrics/week`: воронка, события сайта к прошлой
  неделе, блог, YouTube, деньги; переключатель недель).
- **Продажи**: Лиды (канбан по `stage`, потерянные отдельной колонкой; на телефоне список с выбором этапа; ящик: бриф,
  источник, смета, домен и хостинг, заметки, «Ответить» через `/reply` (при `via: 'none'` текст копируется), «Назначить
  созвон», ссылки на клиента и документы), Клиенты (список, фильтр «с кабинетом», ящик 360: проекты, счета, документы, тикеты с
  ответами, рекомендации, касания), Заявки с сайта и Созвоны (`leads.json`, как в этапе 1), Разведка (этап 2).
- **Поддержка**: тикеты, сортировка по SLA (4 часа), «Отвечено» (только отметка), «Ответ через Поддержку» (команда `ticket`,
  черновик приходит на одобрение), заметка.
- **Производство**: канбан по статусу (draft, active, paused, done), ящик: вехи (чекбокс = `complete_milestone`), сроки
  (`set_deadline`), задачи, issues билдера, статус, заметка.
- **Бэк-офис**: Счета (фильтры, «Напомнить», «Оплачено вручную» и «Аннулировать» с подтверждением, копия ссылки на оплату,
  транзакция в tronscan или tonviewer; TON base64 переводится в hex), Документы, Рекомендации, Отзывы (этап 2).
- **Компания**: рутины (включить, «Запустить сейчас»; 409 `not_started` показывает причину), расходы по отделам против лимита
  (0 = без лимита), уровни доверия (уровень 1 для типов «на замке» только после подтверждения), плейбуки (HQ пока отдаёт `[]`),
  исполнители.

Все записи идут через `/api/admin/hq/...` (сессия, Origin, белый список `PULT_ENDPOINTS` с zod-схемами тел), токен остаётся на
сервере. UI меняется сразу и откатывается при ошибке, итог в тосте. Ошибка HQ показывает «HQ недоступен» с кнопкой
«Повторить», офис не падает.

## События сайта
`trackEvent(name)` на сайте: `chat_open`, `builder_done` (дошли до сметы), `estimate_pdf`, `lead_sent`, `audit_sent`, `ref_click`
(`?ref=`), `pay_view`, `blog_view`; `cabinet_signup` отправляет сервер в колбэке авторизации при первой синхронизации с HQ.
Один раз на событие на просмотр страницы, ничего при Do Not Track или GPC. `/api/events` → HQ `POST /events` (`x-site-token`).
Ответы владельца лидам из веб-чата HQ возвращает в ответе `/chat` полем `ownerReplies`, чат показывает их как «Менеджер Fir Tech».

## Env
| Переменная | Где | Зачем |
|---|---|---|
| `HQ_ADMIN_URL`, `HQ_ADMIN_TOKEN` | сервер | все панели и файлы рендеров; без URL в разработке работает мок |
| `SITE_EVENTS_TOKEN` | сервер, необязательна | токен событий (иначе `HQ_CHAT_TOKEN`); в HQ тот же `SITE_EVENTS_TOKEN` или `WEB_CHAT_TOKEN` |
| `HQ_EVENTS_URL` | сервер, необязательна | адрес `POST /events`, по умолчанию origin `HQ_CHAT_URL` + `/events` |

## Моки
Без `HQ_ADMIN_URL` в разработке `src/lib/pult-mock.ts` отвечает на все маршруты контракта (хаб, лиды по этапам, клиент 360,
проекты с вехами, счета, неделя контента, цифры, компания) и хранит изменения в памяти до перезапуска. Файлы рендеров в
разработке: PNG = SVG-заглушка «демо-рендер», MP4 = 404.
