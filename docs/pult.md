# Пульт v3: офис как хаб и CRM с панелями (2026-11-20)

Владелец: «внедрить всё в наш пиксельный офис и сделать полноценную CRM с отдельными панелями». Длинная колонка панелей
(этапы 1 и 2) убрана: `/admin/office` теперь пиксельный офис на весь экран, отделы открываются панелями поверх него.
Контракт с HQ: `pult-v3` (HQ: `agents/docs/admin-crm-api.md`), прежние маршруты: `agents/docs/admin-crm-api.md`.

## Офис-хаб
- Код: `src/components/admin/hub/hub.tsx` (состояние, опросы, клавиши), `side-panel.tsx`, `panels.tsx` (реестр вкладок),
  `command-palette.tsx`, `notifications.tsx`, `feed.tsx`, `ui.tsx` (`useHqView`, `Offline`, `CopyButton`, `useConfirm`).
- Сцена: `scene.setZoneHits(true)` делает каждую комнату целью клика (после людей, столов, стоек и вывесок),
  `setZoneGlow({roomId: 0|0.5|1})` зажигает мягкую лампу на столах (янтарь = ждёт владельца, лайм = есть работа),
  `zoneRect(roomId)` даёт прямоугольник для бейджа. Обёртка `components/admin/office/pixel-office.tsx`: пропсы `zones`
  (имена, бейджи, уровни, `onZone`), `fill` (на весь контейнер), `personAction` (кнопка «Задачи» в карточке человека).
- Комнаты и панели (`roomPanel` в `src/lib/pult.ts`): кабинет директора и переговорная = Директор; маркетинг; продажи и
  ресепшен = Продажи; поддержка; производство и билдеры = Производство; бэк-офис; серверная = Компания; лаунж ничего не открывает.
- Бейджи и лампы: `GET /admin/hub` → `departments` (одобрения, тревоги, в работе; лампа: одобрения или тревоги = 1, `pending` = 0,5).
- Верхняя полоса: присутствие («На месте» / «Не на месте», пинг раз в минуту как раньше), четыре счётчика (одобрения из
  `/admin/approvals`, новые лиды `stage=new`, счета `issued`, открытые тикеты из `crm/summary`), поиск `⌘K`, тема, меню.

## Клавиши
| Клавиша | Что делает |
|---|---|
| `1`-`6` | Директор, Маркетинг, Продажи, Поддержка, Производство, Бэк-офис |
| `7` | Компания (серверная) |
| `⌘K` / `Ctrl+K` | палитра: отделы, вкладки, команды (Пакет недели, Отчёт, Учения, Расходы, Выпустить одобрения), лиды, клиенты, проекты, счета (`?q=` в HQ), контент открытой недели |
| `Esc` | закрыть ящик, затем панель |
| стрелки | вкладки панели; карточки канбана (Shift+←/→ переносит в соседнюю колонку, Enter открывает); строки счетов |

Цифры и Esc не срабатывают, пока открыт модальный ящик или курсор в поле ввода.

## Панели
- **Директор**: Входящие (уведомления из `hub.inbox`: время, отдел, ссылка `<panel>:<id>` открывает панель на объекте),
  Одобрения (карточки с Одобрить / Править / Отклонить, как раньше), Задачи (доска и ящик задачи), Чат с Директором, Лента
  офиса, Учения.
- **Маркетинг**: Контент (`GET /admin/content?week=`: неделя из 7 колонок, карточки с превью; ящик: MP4 через
  `/api/admin/files/*`, карусель PNG, подписи по платформам с копированием, Одобрить / Правки с текстом / Отклонить /
  Опубликовано (площадка) / Пересобрать, «Из статьи: slug»), Цифры (`GET /admin/metrics/week`: воронка, события сайта к прошлой
  неделе, блог, YouTube, деньги; переключатель недель). `days` (HQ: семь суток, `[{date, site: {...}, blog: {hits}, leads}]`; счётчики прямо в строке дня тоже читаются, от 2 дней): мини-график события и столбики по дням (7 столбиков, подпись «по дням») для каждого события, просмотров блога и лидов. Без `days` остаются две точки с подписью «неделя к неделе».
  Материал `kind: 'profile'` (старт-кит профилей: `platform` `all` или одна площадка, `kit` = `{instagram, youtube, tiktok}` с текстами) показывается одной карточкой с тремя вкладками; текст раздела режется на блоки по пустым строкам, у каждого блока и у раздела целиком своя кнопка «Копировать». Баннер YouTube: файл 2560x1440, текст в безопасной зоне 1546x423.
- **Продажи**: Лиды (канбан по `stage`, потерянные отдельной колонкой; на телефоне список с выбором этапа; ящик: бриф,
  источник, смета, домен и хостинг, заметки, «Ответить» через `/reply` (при `via: 'none'` текст копируется), «Назначить
  созвон», ссылки на клиента и документы), Клиенты (список, фильтр «с кабинетом», ящик 360: проекты, счета, документы, тикеты с
  ответами, рекомендации, касания), Заявки с сайта и Созвоны (`leads.json`, как в этапе 1), Разведка (этап 2).
- **Поддержка**: тикеты, сортировка по SLA (4 часа), «Отвечено» (только отметка), «Ответ через Поддержку» (команда `ticket`,
  черновик приходит на одобрение), заметка. «К клиенту» открывает 360 клиента: по `clientId` тикета (HQ отдаёт его с 2026-11-20: id кабинета или `c:<имя>`), иначе (запасной путь остаётся) поиск `GET /admin/crm/clients?q=` по контакту, затем по имени (точное совпадение или единственный результат); не нашли: тост и список клиентов.
- **Производство**: канбан по статусу (draft, active, paused, done), ящик: вехи (чекбокс = `complete_milestone`), сроки
  (`set_deadline`), задачи, issues билдера, статус, заметка.
- **Бэк-офис**: Счета (фильтры, «Напомнить», «Оплачено вручную» и «Аннулировать» с подтверждением, копия ссылки на оплату,
  транзакция в tronscan или tonviewer; TON base64 переводится в hex), Документы, Рекомендации, Отзывы (этап 2).
- **Компания**: рутины (включить, «Запустить сейчас»; 409 `not_started` показывает причину), расходы по отделам против лимита
  (0 = без лимита), уровни доверия (уровень 1 для типов «на замке» только после подтверждения), плейбуки (строка: роль, дата обновления, число строк, навыки-источники чипами; клик открывает ящик, который берёт `GET /admin/company/playbooks/:role` через прокси (белый список `company/playbooks/<роль>`) и показывает markdown только для чтения: заголовки, списки, таблицы, код, без HTML и ссылок, парсер `src/lib/markdown-lite.ts`, рендер `pult/markdown.tsx`; кнопка «Копировать», подсказка «правки плейбуков через строителя или /playbook»),
  исполнители, инструменты (таблица `tools` из `GET /admin/company`, поле может отсутствовать: тогда пустое состояние). Инструменты сгруппированы по префиксу имени (`web`, `media`, `google`, ...), в строке: имя, отделы чипами, «настроен» да/нет (красная точка и имена env-ключей, если нужны ключи и их нет; серая, если ключей нет, а не настроен адаптер или папка), вызовы и ошибки за сегодня, лимиты словами. На узком экране строка складывается в карточку.

Все записи идут через `/api/admin/hq/...` (сессия, Origin, белый список `PULT_ENDPOINTS` с zod-схемами тел), токен остаётся на
сервере. UI меняется сразу и откатывается при ошибке, итог в тосте. Ошибка HQ показывает «HQ недоступен» с кнопкой
«Повторить», офис не падает.

## События сайта
`trackEvent(name)` на сайте: `chat_open`, `builder_done` (дошли до сметы), `estimate_pdf`, `lead_sent`, `audit_sent`, `ref_click`
(`?ref=`), `pay_view`, `blog_view`; `cabinet_signup` отправляет сервер в колбэке авторизации при первой синхронизации с HQ.
Один раз на событие на просмотр страницы, ничего при Do Not Track или GPC. `/api/events` → HQ `POST /events` (`x-site-token`).
Ответы владельца лидам из веб-чата HQ возвращает в ответе `/chat` полем `ownerReplies`, чат показывает их как «Менеджер Fir Tech».

## Темы и цвета отделов (2026-11-21)
Владелец: «на белом фоне стоит тот же фон, это выглядит некрасиво, построй цвета под разные тематики». Тема выбирается только
кнопкой владельца (`data-theme="light"`), `prefers-color-scheme` в админке не используется (тест это проверяет).

**Слои** (токены в начале `src/app/globals.css`, светлая тема в `:root[data-theme='light']`). Светлая, от тёмного к светлому:
`--color-bg` #d9dfd0 (страница, верхняя полоса) < `--color-inset` #e9eee1 (карточки внутри панели: строки, канбан, плитки) <
`--color-surface` #f7f9f3 (панель, ящики) < `--color-elevated` #fff (палитра, диалоги, меню, тосты). `--color-surface-2/3` = ховер,
дорожки прогресса, активные пункты; `--color-field` = поля ввода. `--color-line` 0.20, `--color-line-strong` 0.55 (границы
контролов не ниже 3:1). Тёмная тема получила те же имена без смены вида. Тени: `--shadow-panel` (боковая панель и ящики поверх
офиса, мягче на тёмной), `--shadow-dialog`. `--color-scrim` под ящиками и диалогами: тёмная полупрозрачная на тёмной, светлая на
светлой. Текст на canvas-слое (погода, кнопки зума) стоит на `bg-surface/85` с blur. Пиксельные карточки и бейджи зон над
офисом остаются «бумагой» (`--color-paper*`, `--color-office-night`): холст одинаков в обеих темах. `--color-danger-ink` = текст на красной кнопке.

**Отделы**: `--color-dept-<id>` (заливка, одна и та же в обеих темах, 3:1 на всех поверхностях), `-soft` (тонированная
поверхность) и `-text` (текст и иконки, AA на всех поверхностях обеих тем), для `director`, `marketing`, `sales`, `support`,
`production`, `backoffice`, `company`. Утилиты Tailwind: `bg-dept-sales`, `bg-dept-sales-soft`, `text-dept-sales-text`. Хелпер
`deptTheme(id)` и `deptOf(rawName)` в `src/lib/pult-theme.ts`. Тест `tests/pult-theme.test.mjs` читает `globals.css`: у каждого
отдела три токена в обоих блоках, AA для текста на каждой поверхности, 3:1 для заливок и границ, запрет `prefers-color-scheme` и
голого белого/чёрного в `src/components/admin`.

**Где применяются**: полоса и точка у заголовка панели отдела, подчёркивание активной вкладки и бейдж вкладки; счётчики верхней
полосы (одобрения = Директор, лиды = Продажи, оплаты = Бэк-офис, тикеты = Поддержка); точка у результата в ⌘K; рутины и расходы
Компании (название отдела цветом); для офиса: цвет лампы на столах и рамки при наведении на комнату (`setZoneGlow(glow, colors)` в
`scene.ts`, цвет читается из CSS-переменной), тень бейджа и подсказки зоны. Янтарная точка лампы остаётся сигналом «ждёт владельца».

**Правило «тонируем только акценты»**: карточки внутри панели остаются нейтральными (`bg-inset`), оттенок отдела только у
полосы, подчёркивания, бейджей, точек, ламп и названий отделов; лайм остаётся общим акцентом (кнопки, прогресс).

## Go-live (2026-11-21)
Владелец: «план go-live: когда проект на 100% готов... таймер 72 часа, обратный отсчёт с секундами, поставь где-нибудь в админке».
- **Где (обновлено 2026-11-21, «большой фон с wow, снизу чеклист»)**: полноэкранная страница `/admin/golive` (сессия как у `/admin/office`, обе темы админки, ссылка «← Офис», переключатель темы). Чип в верхней полосе Пульта («До go-live 2д 13:42:07», до запуска «Go-live: не запущен», после срока красный «Время вышло») теперь обычная ссылка на неё; клавиша `8` и запись «Go-live» в ⌘K делают `router.push`. Боковая панель удалена вместе с кодом. `hub/golive.tsx` держит только `useGolive`, `useClock` и `GoliveChip`; страница: `src/components/admin/golive/` (`golive-page.tsx` сцена и кнопки, `odometer.tsx`, `checklist.tsx`, `stage-field.tsx` + `golive-gl.ts` шейдер). Отдельные часы на странице и у чипа, состояние `goliveOpen` из `hub.tsx` убрано.
- **Сцена**: 100svh, WebGL-шейдер (форк поля главной): медленные ленты шума в лайме и оттенках семи отделов, зерно, свет за курсором, мягкий пульс раз в секунду в такт тику, при «Время вышло» ленты краснеют, по мере готовности списка поле ярче. Цвет фона шейдер берёт из токена `--color-bg` (обновляется на каждом тике), тема из `data-theme`. Дешево: разрешение = половина размера при `devicePixelRatio` не выше 1.5, не больше 30 кадров/с, rAF стоит на скрытой вкладке и вне экрана, при `prefers-reduced-motion` или без WebGL остаётся CSS-градиент `.golive-aurora` на токенах. Цифры `DD : HH : MM : SS` шрифтом `font-brand`: на десктопе одна строка (`min(12vw, 30svh)`), на телефоне две (`DD HH` / `MM SS`, `min(21vw, 13svh)`); каждая цифра отдельный элемент-одометр (колонка из 30 ячеек, пружина, короткий блюр движения), на тике двигаются только изменившиеся, двоеточие мигает раз в секунду (CSS `golive-blink`). До запуска цифры «03 : 00 : 00 : 00» (72 ч) приглушены. Под цифрами подписи, срок в `Asia/Kuala_Lumpur`, кольцо «Готово N из M», «Запустить 72 часа» / «Перезапустить» / «Сбросить» (подтверждения через портал). После срока красные цифры идут вверх и подпись «Время вышло (прошло 3 ч 05 мин)».
- **Чеклист под сценой**: те же 33 пункта блоками, большие карточки в две колонки на десктопе, липкая мини-навигация по блокам с прогрессом (активный блок по IntersectionObserver), чекбоксы мгновенно с откатом и тостом, бейдж ты/Claude, ссылка, время отметки, заметка скрыта до раскрытия строки (клик по заголовку), кнопка «Наверх» появляется, когда сцена ушла с экрана.
- **Часы**: цифры DD : HH : MM : SS, каждая катится колонкой 0-9 (Motion spring, `useReducedMotion` = просто смена текста). Тик раз в секунду только на видимой вкладке, у чипа и у панели свои часы; сервер для часов не опрашивается: срок приходит из GET, обновление раз в 60 с. Размер цифр от ширины карточки (`cqw`), поэтому влезает в панель 440 px и на телефон. Дата срока в `Asia/Kuala_Lumpur` (`GOLIVE_TZ`). После срока цифры идут вверх красным, подпись «прошло 3 ч 05 мин».
- **Хранилище**: `$DATA_DIR/golive.json` (`src/lib/golive-store.ts` на `jsonFile`: очередь, temp + rename), форма `{deadline, startedAt, durationHours, done: {id: ISO}, notes: {id: текст}}`. Только id пунктов, время и короткие заметки (до 300 знаков), всё остальное отбрасывает `sanitize`. Бэкапить вместе с `leads.json`. «Сбросить» снимает таймер и оставляет отметки.
- **API** `/api/admin/golive` (сессия, Origin, только JSON): `GET` = состояние + пункты + прогресс; `POST` `{action:'start', hours?}` (по умолчанию 72), `{action:'reset'}`, `{action:'toggle', id, done}`, `{action:'note', id, text}`.
