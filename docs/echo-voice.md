# Голос Echo: браузерный или серверный (Piper)

Замер сделан 2026-10-18 на локальном Mac (Apple M1 Pro, 8 ядер), не на сервере. Продакшен не
трогали. Piper 1.8.0 (`pip install piper-tts` во временном venv вне репозитория), голоса
`ru_RU-{denis,dmitri,irina,ruslan}-medium`, 5 типичных ответов Echo по 2 предложения (4-7 секунд
речи каждый). Ухом голоса я оценить не мог: качество звучания решает владелец (образцы WAV лежат
в временной папке сессии, при необходимости пересинтезируются командой ниже).

## Что измерено

Холодный запуск: отдельный процесс на каждую фразу (загрузка модели входит в время), замер
`/usr/bin/time -l`. Среднее по 5 фразам:

| Голос | Время, с | Длина речи, с | RTF | Пик RAM, МБ | WAV, КБ |
|---|---|---|---|---|---|
| denis | 1.35 | 5.44 | 0.25 | 238 | 234 |
| dmitri | 1.22 | 4.61 | 0.26 | 243 | 198 |
| irina | 1.28 | 6.58 | 0.20 | 244 | 283 |
| ruslan | 1.29 | 5.08 | 0.25 | 259 | 219 |

Тёплый режим (модель загружена один раз, как в HTTP-сервисе): синтез фразы 0.13-0.25 с, RTF 0.03,
загрузка модели около 1 с при старте. Сквозной запрос к `piper.http_server` (dmitri, фраза про
заявки, localhost): 0.14-0.18 с до готового WAV, процесс держит около 262 МБ RSS, файл голоса 63 МБ.
WAV 22 кГц, 16 бит, моно: около 43 КБ на секунду речи (200-300 КБ на ответ).

Выводы по цифрам:
- Скорость не проблема: тёплый синтез в 30 раз быстрее речи. Первая секунда ответа задаётся
  Claude, а не голосом.
- Цена: около 250 МБ RAM постоянно на один голос и одно ядро на долю секунды на ответ.
- Размер ответа на сеть: 200-300 КБ на реплику, заметно только на плохой мобильной связи.
- На слабой VPS (1 vCPU) ожидаем RTF в 3-6 раз хуже (0.1-0.2 тёплым), то есть до полутора секунд
  на ответ. Это нужно проверить на месте перед включением.

## Браузерный голос (speechSynthesis)

Бесплатный, без RAM на сервере, ответ слышен сразу (начинает говорить, не дожидаясь файла).
Качество зависит от ОС: на macOS и iOS русские голоса хорошие, в Chrome на Windows и Android
звучат заметно механичнее, в Firefox на Linux русского голоса может не быть вовсе. Мы выбираем
мужской русский голос по имени, если он есть.

## Рекомендация

1. Сейчас оставить браузерный голос как есть. Он работает у владельца, не стоит памяти и не
   добавляет отказов.
2. Серверный голос включать, только если браузерный звучит плохо на устройствах владельца.
   Тогда брать `ru_RU-dmitri-medium` (мужской, самый быстрый и компактный из четырёх, подходит
   обращению «сэр»); `denis` как запасной. Решать по прослушиванию образцов.
3. Условия включения на сервере: свободные 300 МБ RAM рядом с Vibely и Fir Tech, отдельный
   процесс (PM2) только на 127.0.0.1, проверка RTF на самой VPS.

## Как включить (когда решите)

Код готов и ничего не делает, пока не задан `ECHO_TTS_URL`. Тогда `/api/admin/echo/tts` проксирует
текст (до 600 символов) на Piper, только для владельца, 60 запросов за 10 минут на сессию, и
принимает только адрес на loopback (`127.0.0.1`, `localhost`, `[::1]`, http). Без переменной эндпоинт
отвечает 404, и страница сама говорит браузерным голосом. При ошибке сервера один ответ тоже
озвучивается браузером.

```
pip install piper-tts flask
python -m piper.download_voices ru_RU-dmitri-medium --download-dir /var/www/firtech/shared/voices
python -m piper.http_server -m /var/www/firtech/shared/voices/ru_RU-dmitri-medium.onnx --port 5000
# в shared/.env.production:
ECHO_TTS_URL=http://127.0.0.1:5000/synthesize
```

Piper отдаёт WAV с заголовком text/html, прокси выставляет `audio/wav` сам.

## Как повторить замер

```
python -m piper -m voices/ru_RU-dmitri-medium.onnx -f out.wav <<< "Доброе утро, сэр."
/usr/bin/time -l python -m piper -m voices/ru_RU-dmitri-medium.onnx -f out.wav <<< "Доброе утро, сэр."
```
