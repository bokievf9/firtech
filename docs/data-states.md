# Состояния загрузки и ошибки (2026-11-22, пункт 7 ревью владельца)

Владелец: «На каждом этапе, где идёт обработка данных, ставить анимации загрузки и выводить все ошибки».
Правило: нет места, где нажали и ничего не видно, и нет ошибки, проглоченной молча.

## Единая система

| Что | Где |
|---|---|
| Карта ошибок: код или HTTP-статус -> текст RU/EN, подсказка, можно ли повторить; неизвестная ошибка показывается с кодом `E-<КОД>-<ЧЧММ>` | `src/lib/errors.ts` (`describeError`, `codeFromBody`, `fetchJson` с таймаутом 20 с) |
| JSON-ответ ошибки роутов `{ok:false, error:{code, message}}` с правильным статусом, `withTimeout` для внешних вызовов | `src/lib/api-error.ts` |
| Одна анимация загрузки: кольцо `.spinner` (лайм через `currentColor`, медленнее при `prefers-reduced-motion`), `.skeleton` (шимер) | `globals.css`, `components/ui/spinner.tsx`, `skeleton.tsx` |
| Кнопка ожидания: спиннер, `aria-busy`, повторный клик игнорируется, «Отправляем…» | `components/ui/pending.tsx` |
| Ошибка рядом с действием: `role="alert"`, текст, что делать, «Повторить», код для поддержки | `components/ui/error-note.tsx` |
| `loading.tsx` (кабинет, Пульт, решения, продукты, ИИ-отделы), `error.tsx` (весь `[locale]`, кабинет, Пульт), `global-error.tsx` | `src/app/**`, `components/ui/route-states.tsx` |
| Пульт: `PanelError` (причина + «пробуем сами»), `PanelWait` (скелетон), `Offline` с кнопкой «Повторить» в состоянии ожидания, `errText` знает общую карту | `components/admin/control/panel-error.tsx`, `hub/ui.tsx`, `control/api.ts` |

Тосты Sonner не ставились (зависимость не нужна): в Пульте уже есть свой `Toast`, на сайте ошибка стоит рядом с кнопкой.
Сервер-роуты публичной части (`chat`, `lead`, `audit`, `slots`, `agent-demo`) отдают новую форму ошибки; кабинет и Пульт
остаются на `{ok:false, error:'код'}` (контракт покрыт тестами и HQ), клиент читает обе формы (`codeFromBody`).

## Нужно от HQ

HQ не менялся. Что улучшило бы состояния (контракты, ничего не сломается, если HQ пока не отдаёт):

1. **Код ошибки в теле при любом не-2xx.** Сейчас часть ответов HQ (особенно 4xx/5xx от прокси) приходит HTML или пустым телом, сайт
   по статусу выводит общий текст. Контракт: `{ok:false, error:"<code>", message?:"<ru>"}`, коды из списка `invalid`,
   `not_found`, `rate_limited`, `unavailable`, `too_large`, `unsupported_type`, `auth_required`.
2. **`Retry-After` (секунды) в ответах 429 и 503**, чтобы сайт писал «повторите через N секунд».
3. **Статус лида при приёме `POST /lead`**: `{ok:true, id, queued:boolean}`, где `queued:true` значит «HQ принял в очередь, обработает позже».
   Тогда сайт покажет «HQ занят, заявка сохранена и уйдёт позже». Сейчас сайт видит только `hqLeadId` или `null`.
4. **Здоровье по каждому источнику в `GET /status`**: `{services:[{id, state, checkedAt, error?:code}]}`, чтобы страница статуса и
   Пульт показывали причину сбоя, а не только цвет.
5. **Идентификатор запроса `x-request-id`** в каждом ответе: сайт показал бы его как код для поддержки вместо своего `E-…`.
