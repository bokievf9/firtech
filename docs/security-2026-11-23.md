# Security fixes 2026-11-23: what the owner applies on the server

The code side is in the branch `security-2026-11-23` (one commit per finding of the review). These steps
are done by hand on the server or in Supabase/GitHub; until they are done, the code falls back safely.

## 1. HQ_CABINET_TOKEN (P1-4)

After HQ accepts the scoped token (agents side, `CABINET_TOKEN`): the same value in
`/var/www/firtech/shared/.env.production` as `HQ_CABINET_TOKEN=...`, then `pm2 restart firtech --update-env`
(as `deploy`). Until then the cabinet uses `HQ_ADMIN_TOKEN` and logs one warning
`[cabinet] HQ_CABINET_TOKEN is not set`. The secret goes through the hidden macOS dialog, never chat.

## 2. Supabase migration 0004 (P1-3)

Supabase dashboard -> SQL editor: paste `supabase/migrations/0004_profiles_column_grants.sql`, run (after 0003).
Check: in the cabinet the profile still saves (name, Telegram, switches), and

```sql
select grantee, privilege_type, column_name from information_schema.column_privileges
where table_name = 'profiles' and grantee = 'authenticated' and privilege_type = 'UPDATE' order by 3;
```

lists only the profile fields (no `email`, `hq_synced_at`, `id`). Also in Supabase -> Authentication: Confirm
email ON, Secure email change ON, Leaked password protection ON, minimum password length >= 10.

## 3. Backup encryption (P1-6)

On the Mac: `age-keygen -o ~/.config/age/firtech.key` (keep it, never on the server), copy the `age1...` line.
On the server: `sudo apt-get install -y age`, add `BACKUP_AGE_RECIPIENT=age1...` to
`/var/www/firtech/shared/.env.production`. Without it the daily backup sends only a summary with a warning.
Decrypt a backup: `age -d -i ~/.config/age/firtech.key firtech-leads-<day>.json.age > leads.json`.

## 5. nginx (P1-2, P2-12, P2-15)

What changes: the shared snippet sets `X-Forwarded-For $remote_addr` (no appended client header) and
`X-Forwarded-Host $host`; new per-IP zones `firtech_login` (10 r/min on `/api/admin/login`), `firtech_chat`
(30 r/min on `/api/chat` and `/api/demo-agent/*`), `firtech_csp` (`/api/csp-report`), `/api/audit` on
`firtech_api` (10 r/min, burst 3), `limit_req_status 429`.

From the Mac (folder `~/fir-tech/firtech` after the merge):

```bash
scp -i ~/.ssh/id_ed25519_firtech infra/nginx/firtech-proxy.conf infra/nginx/firtech.conf deploy@201.79.122.133:/tmp/
```

On the server (`ssh -i ~/.ssh/id_ed25519_firtech deploy@201.79.122.133`):

```bash
sudo cp /etc/nginx/snippets/firtech-proxy.conf /etc/nginx/snippets/firtech-proxy.conf.bak-2026-11-23
sudo cp /etc/nginx/sites-available/firtech /etc/nginx/sites-available/firtech.bak-2026-11-23
# 1) the snippet has no Certbot parts: replace it as is
sudo install -o root -g root -m 644 /tmp/firtech-proxy.conf /etc/nginx/snippets/firtech-proxy.conf
# 2) the site file holds Certbot's 443 block: merge by hand, never overwrite
diff -u /etc/nginx/sites-available/firtech /tmp/firtech.conf
sudo nano /etc/nginx/sites-available/firtech
```

In the editor:
- replace the two `limit_req_zone` lines at the top with the block of five zones plus `limit_req_status 429;`
  from `/tmp/firtech.conf`;
- in the server block that serves `firtech.pro` over HTTPS (the one with `listen 443 ssl`), paste the new
  locations `= /api/admin/login`, `= /api/audit`, `= /api/chat`, `^~ /api/demo-agent/`, `= /api/csp-report`
  right before `location ^~ /api/admin/ {`.

Then:

```bash
grep -rn "media\|proxy_add_x_forwarded_for" /etc/nginx/sites-enabled /etc/nginx/snippets
# every /media/ or /agent/ block must include /etc/nginx/snippets/firtech-proxy.conf; no proxy_add_x_forwarded_for left
sudo nginx -t && sudo systemctl reload nginx
```

Check from the Mac (after about six quick tries the answers turn 429; the app limits too, so this only shows the chain works):

```bash
for i in $(seq 1 12); do curl -s -o /dev/null -w '%{http_code} ' -X POST https://firtech.pro/api/admin/login -H 'content-type: application/json' -H 'origin: https://firtech.pro' -d '{"password":"x"}'; done; echo
curl -sI https://firtech.pro/ | grep -i content-security-policy-report-only
```

Rollback: `sudo cp` the two `.bak-2026-11-23` files back, `sudo nginx -t && sudo systemctl reload nginx`.
